# Duckln Intake Checklist

Use this before drafting requirements.

- [ ] What exact user pain is being solved?
- [ ] Which user segment is this for?
- [ ] What release is this in?
- [ ] Is this a core flow or polish?
- [ ] What command types are involved?
- [ ] What privacy-sensitive information may appear?
- [ ] What mode behavior differs?
- [ ] What provider behavior differs?
- [ ] What is the worst-case failure?
- [ ] How will success be measured?
- [ ] What is explicitly out of scope?
